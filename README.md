# PanAssets — Financial Series Assets

A personal finance PWA (React + TypeScript + Vite) backed by Supabase. Tracks bank/investment account balances, FX conversions, Dime stock trades, FCD (foreign-currency / gold), and monthly salary allocation.

## Stack

- **React 19** + **Vite 7** + **TypeScript**
- **Supabase** (`@supabase/supabase-js`) — Postgres backend
- **Tailwind CSS 3** + **shadcn/radix-ui** components
- **recharts** / **chart.js** for charts, **tesseract.js** for receipt OCR
- **vite-plugin-pwa** for installable PWA (iOS/Android)

## Setup

```bash
npm install
cp .env.example .env   # then fill in your Supabase credentials
npm run dev
```

### Environment variables

Create `.env` (not committed) with:

```
VITE_SUPABASE_URL=your-project-url
VITE_SUPABASE_ANON_KEY=your-anon-key
```

## Local testing with fake data

Run the whole app on a generated dataset — no Supabase project, no Docker, and
no contact with the real database:

```bash
npm run dev:mock
```

That runs `vite --mode mock`, which loads `.env.mock` (`VITE_USE_MOCK=true`).
[`src/supabaseClient.ts`](src/supabaseClient.ts) then exports an in-memory fake
instead of the real client, so all 14 call sites get mock data without any page
needing to know.

| Command | What it does |
|---|---|
| `npm run dev:mock` | Dev server on fake data |
| `npm run preview:mock` | Production build + preview, on fake data |
| `npm run dev` / `npm run build` | Unchanged — real Supabase project |

### Why real data is safe

- **`createClient()` is never called in mock mode.** It appears exactly once, in
  `src/supabaseClient.ts`, on the branch that mock mode skips — so no client,
  no URL, no anon key, no connection is ever constructed.
- **The mock has no way to reach the network.** `src/mock/` contains no `fetch`,
  `XMLHttpRequest`, or `WebSocket`. Verified at runtime: with every page
  exercised, the devtools network panel records **zero** xhr/fetch/websocket
  requests.
- **Mock code never ships.** `VITE_USE_MOCK` is folded to a constant at build
  time, so a real `npm run build` tree-shakes the mock module out entirely —
  the production bundle contains none of its markers.
- **Opt-in per Vite mode.** Mock mode only turns on via `--mode mock`; a plain
  `npm run dev` behaves exactly as before. `.env.mock` holds no credentials, so
  it is committed; your real `.env` stays git-ignored.
- **Writes stay in memory.** Saving a transaction, salary allocation, or FCD
  entry mutates a JavaScript array, never Postgres.

### What's in the dataset

Generated by [`src/mock/fixtures.ts`](src/mock/fixtures.ts) from a fixed seed, so
every run produces identical data (good for screenshots and diffs). Covers
**2025-01 → 2026-09**:

| Table | Rows | Notes |
|---|---|---|
| `pantagon_financial_transactions` | 332 | Opening balances, salary, rent, spending, transfers |
| `pantagon_financial_accounts` | 7 | 6 active + 1 inactive, to exercise the `onlyActive` filter |
| `pantagon_financial_salary_logs` | 21 | One per month, with the `allocations` JSON |
| `pantagon_financial_fx` | 28 | Mostly THB→USD, a few reversals |
| `pantagon_financial_fcd` | 38 | FX / GOLD_BUY / GOLD_SELL / INTEREST / TRANSFER |
| `dime_trades` | 87 | STOCK 63, FUND 11, GOLD 13 |
| `dime_gold` | 13 | Gold tickets |

Totals land in the millions of THB: **~3.8M net worth** across six accounts
(SCB, KBank MAKE, TTB, Dime, SSO, Cash), ~$131k invested in stocks and ~$113k of
FCD cash. Balances never go negative and no position is ever sold short. Pass a
different seed to `createSeedData(seed)` for another — still deterministic — set
of numbers.

### Notes

- [`src/mock/mockSupabaseClient.ts`](src/mock/mockSupabaseClient.ts) implements
  the slice of the Postgrest builder this app uses: `select` / `insert` /
  `update` / `upsert` / `delete`, `eq`-style filters, `order`, `limit`, `single`,
  `maybeSingle`. Unknown tables return a Postgres-shaped `42P01` error, so typos
  surface the same way they would for real.
- The store is in memory only — **a page reload resets everything back to the
  fixtures.**
- `VITE_MOCK_LATENCY` (default 150 ms) fakes request latency so loading
  skeletons stay visible.
- In the devtools console, `__mock.db.tables` inspects the rows and
  `__mock.reset()` restores pristine fixtures without a reload.

## Supabase tables

All app tables use the `pantagon_financial_*` prefix:

| Table | Purpose |
|---|---|
| `pantagon_financial_transactions` | Bank/account IN/OUT ledger |
| `pantagon_financial_fx` | Currency conversion records |
| `pantagon_financial_stock_trades` | Dime broker stock trades |
| `pantagon_financial_fcd` | Foreign-currency deposit / gold |
| `pantagon_financial_salary_logs` | Monthly salary allocation history |
| `pantagon_financial_accounts` | Account catalog (names, icons, ordering) for UI dropdowns |

> **Note:** Row Level Security is currently disabled on these tables. The app uses the public anon key client-side with no auth layer — anyone with the key can read/write. Add Supabase Auth + RLS policies before exposing this publicly.
